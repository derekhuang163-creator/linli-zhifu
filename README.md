# 邻里智服（Linli Zhifu）

AI 驱动的社区可信上门服务平台。

## 当前 MVP 功能

- 微信小程序用户端：需求输入、风险初筛、服务者推荐、创建订单、订单确认与履约时间轴
- 服务者工作台：查看分配订单、接单、确认到达、开始服务、完成服务
- 后端 API：需求解析、匹配、订单持久化、订单状态机、履约历史
- 服务者审核接口与开发版管理后台
- Node.js 自动化测试：订单状态流转和非法状态跳转

## 本地启动后端

在终端进入 `server/`：

```bash
npm install
npm test
npm run dev
```

服务启动后访问 `http://localhost:3000/health` 检查健康状态。没有 `OPENAI_API_KEY` 时，需求解析使用规则演示模式。

如需启用 AI，在 `server/.env` 配置：

```text
OPENAI_API_KEY=你的API密钥
OPENAI_MODEL=你有权限使用的模型名称
```

不要把密钥提交到 GitHub。

## 小程序连接后端

修改 `miniapp/config.js`：

```js
const API_BASE_URL = "https://你的服务器域名";
module.exports = { API_BASE_URL };
```

正式微信小程序需要配置 HTTPS request 合法域名。当前仓库默认 `API_BASE_URL = ""`，表示使用本地演示模式；本地演示数据仅保存在当前小程序运行内存中，不等于线上持久化服务。

## 当前重要限制

- `/api/auth/dev-login` 是开发登录，不是正式微信身份认证。
- 管理后台 API 支持 `ADMIN_API_TOKEN` Bearer Token；生产环境未配置 Token 时后台 API 默认拒绝访问。浏览器只在当前会话保存 Token。
- 开发登录、下单写入、演示用户订单状态更新及演示服务者履约接口在 `NODE_ENV=production` 下被禁用；正式身份与权限认证尚未接入，因此当前版本不能直接承接真实生产订单。
- 支付、退款、保险、真实定位、真实距离排序尚未接入。
- 服务者工作台目前使用演示服务者身份；上线前必须增加服务者登录、身份核验和订单授权。
- 正式上线前需要安全审查、隐私合规、支付结算合规和端到端测试。

## 产品路线

1. 稳定用户下单—服务者履约—用户验收的完整状态链路。
2. 完成微信用户登录、服务者身份与权限。
3. 将 JSON 文件存储迁移到正式数据库并备份。
4. 增加管理员认证、审核操作和审计日志。
5. 进行支付、退款、售后、保险和隐私合规接入。


## 管理后台安全配置

本地开发可不设置 Token。部署环境需设置 `NODE_ENV=production` 和一个随机的 `ADMIN_API_TOKEN`（建议至少 32 字节随机值），并通过 HTTPS 访问后台。不要把 Token 写进代码仓库或发给用户。生产环境在完成微信用户/服务者身份认证、订单权限校验及正式数据库迁移前，不应开放真实下单运营。
